# Design — Remotion port of the approved retention edit (content-identical A/B)

Date: 2026-10-30 · Status: awaiting approval · Parent design: `2026-10-30-cats-retention-loop-design.md` (approved)

## Intent
Give the owner a fair renderer-vs-renderer judgment: re-cut `remotion-video`'s `CatsShort`
composition to the **same content and same retention design** already shipped in
`cats-hyperframes`, so the only difference between the two MP4s is the framework.

## Goals
- Identical content to the HyperFrames cut: 18 Flow images (`flow-laptop/numbered/img-01..18.jpg`),
  the 18-caption script (incl. captions 16–18 for VO6 v3), VO `cats-01..06` with the v3 loop
  bridge, the three −18dB SFX (`hook-stamp`, `whoosh`, `seam-chime`).
- All retention levers ported 1:1: title → 1.2s transparent overlay + chip
  `KILL A CAT? YOU'D BE EXECUTED`, VO from t=0, probed VO-driven schedule (0.12s gaps, 0.30s tail),
  word-pop captions (0.04s stagger, gold keywords from the pinned list), punch-in per slide
  (scale 1→1.05→1), no static slides, slide 1 without fade, SFX at hook/5 clip starts/seam,
  video ends when VO6+chime end.
- Output: `remotion-video/out/cats-shorts-retention.mp4`. **Baseline `out/cats-shorts-9x16.mp4`
  and `src/CatsShort.tsx` history stay untouched** (render artifact kept for side-by-side).
- Repeatable schedule: a small script probes `public/vo/*.mp3` → writes `src/catsSchedule.ts`
  constants (browser can't ffprobe at render time).

## Non-goals / anti-goals
- No changes to the HyperFrames version; no new images, VO lines, or effects beyond the parent design.
- No new npm dependencies (no test framework — assert-based node script, like the parent plan used).
- Baseline composition `CatsShort` source is replaced in place by the new cut (old version is in
  git); the old MP4 artifact is the baseline for comparison.

## Constraints
- Remotion idioms only: `<Sequence>` per timed element, `useCurrentFrame()` local-frame animation,
  `staticFile()` assets, deterministic (no Date/random/network), fps 30, 1080×1920.
- Composition duration must equal probed schedule (≈59.2s → 1776 frames); `Root.tsx` duration updated.
- Frame-rounded schedule: all times ×30 rounded; gaps must stay ≥0 after rounding.

## Approaches considered
1. **In-place rework of `CatsShort.tsx` + generated `catsSchedule.ts` (chosen)** — one component,
   schedule constants generated by probe script; baseline preserved as git + existing MP4.
2. Separate `CatsShortRetention` composition — rejected: duplicate file churn, git already
   preserves the baseline.
3. Python generator emitting TSX (mirror of `gen-hf.py`) — rejected: overkill for one static
   component; the probe script covers the only computed part.

## The how (pinned, inherited from parent design)
- `scripts/probe-schedule.mjs`: ffprobe durations → gap 0.12 → `TOTAL = Σdur + 5×0.12 + 0.30`
  → 3 slides per clip? **No — 18 slides / 6 clips = 3 slides per clip, slot = clip/3** (same as parent).
- Components: `Slide` (KB + punch via local frame, in/out push TR=0.22s), `Caption` (word spans,
  stagger 0.04s, keyword list = parent's pinned 18 keywords, rule + fade-out), `TitleOverlay`
  (words 0.10+i×0.08, chip 0.55, rule 0.75, fade 1.0→1.2, transparent), audio `<Sequence>`s for
  VO (start+probed+0.05), SFX (stamp@0, whoosh@5 clip starts, chime ending exactly at root end).
- Last slide holds to root end; Ken Burns direction zoom-in on slides 1 and 18.
- Assets: copy 18 Flow images → `public/cats/` (replacing img-19..24 orphans: delete them),
  copy VO6 v3 + leveled SFX → `public/vo/`, `public/sfx/`.

## Verification (builder's gate)
- `node scripts/check-schedule.mjs` — asserts schedule arithmetic + generated constants match
  probed durations (the RED/GREEN test).
- `npm run render` → ffprobe: duration ≈ schedule (±0.1s), audio==video, 1080×1920;
  extract first/last frames + t=0.9 hook frame and read them; loop-line caption check.

above as delete — my call, git + baseline MP4 keep them recoverable).
